# HappyFreeTime 人机协作与学习手册

_从原始讨论提炼出的长期协作方式；用于控制范围并让用户真正掌握项目_

---

## 🎯 协作目标

Codex 的价值是加速代码检索、实现、测试和审查；用户的核心责任是定义问题、判断产品规则、选择取舍并验证自己能解释结果。项目是否属于用户，不取决于每行代码由谁输入，而取决于用户能否独立解释、验证和修改它。

## 🔄 行为切片循环

每个切片使用“预测—核对—实验—实现—复述—沉淀”循环。它解决了两种极端：每个接口都暂停会割裂上下文，整个 M1 一次做完又会让用户跟不上。

| 阶段 | 用户负责 | Codex 负责 | 产物 |
| --- | --- | --- | --- |
| 预测 | 写出自己的理解和疑问 | 提供场景，不提前给答案 | 初始心智模型 |
| 核对 | 比较预测与代码行为 | 定位接口、数据和测试证据 | 纠正后的模型 |
| 实验 | 修改一个输入或断言 | 控制实验范围、解释结果 | 可重复的学习证据 |
| 实现 | 确认产品规则和验收 | 最小实现、测试和回归 | 通过验证的变更 |
| 复述 | 独立解释链路与取舍 | 只纠错和追问 | 面试表达草稿 |
| 沉淀 | 确认掌握等级 | 更新学习文档 | 可复习的里程碑记录 |

## 🧩 切片大小

一个切片应当能回答一个完整问题，例如：

- 为什么用户没说日期时可以默认，但说了模糊日期时必须反问
- 严格预算缺少金额如何触发 Gate 和 interrupt/resume
- Planner 为什么在评分后仍要执行硬约束复检
- API 如何区分新规划请求和反问答案

下面这些通常太小或太大：

- 太小：逐个解释私有 helper、每增加一个字段都停一次
- 太大：一次完成整个 M1、一次讲完整个前后端和数据库

## 🧪 掌握方式

每个切片至少完成一种主动验证：

- 改一条输入，预测输出变化
- 删除或改变一个校验，观察哪条测试失败
- 为已知边界补一条断言
- 从 HTTP 请求追到领域对象和持久化记录
- 在不看文档时画出链路并解释职责边界

只读完解释不算掌握；能够制造一个受控错误并用测试定位，才形成稳定记忆。

## 🎤 面试证据

每个里程碑复盘都要积累以下材料：

- 业务问题和约束
- 用户参与的关键决策
- 被否决的方案及原因
- 核心不变量
- 对应代码、测试和提交
- 一次真实问题或认知修正
- 30 秒、2 分钟和深挖版本的项目讲解
- 仍未完成的真实工程缺口

不得写尚未测量的延迟、成功率或成本数字。面试表达先建立证据，再追求包装。

## 🧹 控制过度设计

- 只实现本切片验收标准
- 不为未来功能创建空接口、基类或配置项
- 新增异常处理必须对应已知失败模式和测试
- 只有真实重复或复杂业务规则才值得提取 helper
- 完成后检查是否存在可以删除的代码
- 里程碑末尾再做独立的架构和代码审查，不把所有仪式塞进每个小修改
