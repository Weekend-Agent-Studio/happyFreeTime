# HappyFreeTime 设计阶段知识总结

_当前面试复习主索引 · 设计阶段材料，最终说法需结合里程碑学习证据_

---

下面把设计阶段遇到的知识整理成一套“知识地图 + 面试问答”。重要程度按 AI Agent 应用开发岗位划分：

- `S`：高频核心，必须能结合项目讲清楚
- `A`：工程加分项，应理解原理和取舍
- `B`：扩展知识，知道适用场景即可

**一张知识地图**

```
用户交互层：REST、SSE、RunEvent、ResponseEnvelope、Human-in-the-loop
编排控制层：LangGraph、State、Node、Edge、Interrupt、Checkpoint、Agent Loop
领域能力层：Router、Service、Provider、Tool、Verifier、Saga
数据持久层：SQLite、WAL、SQLAlchemy、Alembic、Redis、DuckDB
开放集成层：MCP Server / Client、Tool、Resource
质量工程层：Pydantic、Trace、OpenTelemetry、LangSmith、Evaluation
```

记忆原则：**Graph 管流程，State 管过程数据，Service 管业务，Provider 管外部服务，Event 管前端展示，数据库管事实。**

## Agent 架构

### `S` Q1：Workflow、Agent Loop 和 Harness 有什么区别？

**答：** Workflow 预先定义主要节点和流转规则，适合权限、订单、反问、校验等确定性业务；Agent Loop 由模型反复进行“观察、决策、调用工具、继续推理”，适合开放探索；Harness 是围绕模型循环建设的上下文管理、工具执行、权限、压缩、恢复和观测等运行时系统。

**项目回答：** 周末规划既有语义理解，也有确认、路线复核和执行事务，因此适合“外层受控 Graph + 局部 Planner Loop”，而不是完全自由的单模型循环。

**记忆：** Workflow 是流程图，Loop 是模型自己走，Harness 是保障模型走得动且不越界的整套运行环境。

### `S` Q2：多 Agent 是否已经过时？

**答：** 没有过时，但“每个步骤都包装成 Agent”通常会增加延迟、Token、状态转换和调试成本。应按决策自主性划分：只有需要独立上下文、工具集或循环推理的模块才叫 Agent；规则补全、校验、路由更适合普通代码节点。

**项目回答：** RouterExtractor 可以使用一次 LLM，Enrichment、NeedQuestion Gate、Verifier 应尽量确定性实现，Planner 才保留有限循环。

**记忆：** 不是 Agent 越多越智能，而是每份自主性都必须有必要性。

### `S` Q3：LangGraph 的价值是什么？

**答：** Graph 的价值不在“画了多少节点”，而在于显式状态、条件分支、循环、人工中断、Checkpoint 恢复和执行可观测性。简单问答没必要用 Graph；跨轮反问、方案确认、路线复核重规划和订单补偿才真正体现它的价值。

**记忆：** Graph 擅长处理“任务还没结束，但现在必须暂停或回头”。

### `S` Q4：为什么推荐代码路由，而不是让 LLM 直接决定是否下单？

**答：** LLM 负责理解语义并输出结构化意图；代码根据状态、权限和确认令牌决定流程。用户是否下单由用户确认，代码验证确认是否有效，模型不能自己授予权限。

```
LLM：识别“用户确认了第二套方案”
代码：检查方案 ID、确认状态、权限、幂等键后进入 execution
```

**记忆：** 模型提议，用户授权，代码裁决。

### `A` Q5：Beam Search 是什么，在规划里怎么用？

**答：** 每一步不只保留一个候选，而是保留评分最高的 `K` 个候选继续扩展，避免早期局部最优导致最终无解。它适合“活动 → 餐厅 → 路线”等组合搜索，但本项目首版可采用小规模候选集和规则排序，不必上复杂算法。

**记忆：** 贪心只留冠军，Beam Search 留前 `K` 名继续比赛。

## State、事件与前后端

### `S` Q6：Graph State、RunEvent 和 ResponseEnvelope 有什么区别？

**答：** State 是 Graph 内部节点之间共享的执行状态；RunEvent 是运行过程中通过 SSE 推给调用方的增量事件；ResponseEnvelope 是本轮结束后的最终结构化响应。

```
State：约束、候选、验证结果、内部错误
RunEvent：正在搜索、方案已生成、路线校验失败
ResponseEnvelope：最终状态、plan_id、方案、待补问题
```

ResponseEnvelope 不是把完整 State 原样返回，二者应通过映射隔离内部信息。

**记忆：** State 给后端流程，Event 给过程展示，Envelope 给最终结果。

### `S` Q7：“前端不解析模型文本判断展示地图”是什么意思？

**答：** 前端不应从“我已经为你找到三套方案”这句话猜测该展示方案卡片，而应读取结构化字段：

```
{"event_type":"plans_ready","payload":{"plans":[]}}
```

模型文本可以展示，但不能充当 UI 控制协议。

**记忆：** 文本给人看，类型字段给程序判断。

### `S` Q8：SSE 是什么，为什么适合 Agent？

**答：** SSE 是服务器通过一个 HTTP 长连接持续向客户端单向推送事件的机制，适合 Agent 的节点进度、工具调用和增量文本。最终结果仍可作为最后一个完成事件或通过响应查询获得。需要客户端双向高频通信时才更倾向 WebSocket。

**记忆：** SSE 是服务端持续播报；用户的新消息仍走普通 HTTP 请求。

### `S` Q9：Checkpoint 是什么，为什么不是业务数据库？

**答：** Checkpoint 保存 Graph 某一时刻的执行状态，使反问、确认和长任务可以在进程重启后恢复；订单、方案、用户资料则是业务事实。不能从 Checkpoint JSON 反推订单状态。

**记忆：** Checkpoint 是书签，业务表是账本。

## 工具、Provider 与真实世界

### `S` Q10：Tool、Service、Provider 和 Router 有什么区别？

**答：** Router 决定下一步去哪；Service 实现领域用例；Provider 屏蔽高德、天气或 Mock 等具体实现；Tool 是可由模型或编排器调用的能力接口。

```
Router → PlanningService → RouteProvider → Amap API
```

并非所有 Service 都要暴露为 Tool，也不是所有 Tool 都必须由 LLM 自由调用。

**记忆：** Router 选路，Service 办事，Provider 找供应商，Tool 提供可调用入口。

### `S` Q11：Mock 层是什么？以后如何替换真实工具？

**答：** Mock 不是简单造随机数据，而是实现与真实 Provider 相同的数据契约，用可复现方式模拟搜索、库存、预订和失败。上层依赖接口：

```
RouteProvider ← AmapRouteProvider / MockRouteProvider
BookingProvider ← MockBookingProvider / RealBookingProvider
```

替换 Provider 时，Graph 和领域层不应重写。

**记忆：** Mock 模拟的是契约和行为，包括成功、失败、超时和幂等，而不只是返回假 JSON。

### `A` Q12：为什么先本地召回，再用高德复核？

**答：** 本地数据适合廉价地从大量 POI 中召回候选；高德适合对少量最终候选计算真实路网距离、交通方式和耗时。它不是“高德实现困难后的兜底”，而是成本、延迟、配额和可复现性之间的两阶段设计。

**记忆：** 本地负责缩小范围，真实 Provider 负责核验现实可行性。

### `A` Q13：真实工具降级是什么意思？

**答：** 高德超时或限流时，系统根据风险选择缓存结果、本地估算、减少功能或明确提示不可用。降级结果必须标记来源和置信度，不能把直线距离伪装成真实路线。

**记忆：** 降级不是假装成功，而是降低能力并诚实说明。

## 数据库与事务

### `S` Q14：SQLite、SQLAlchemy、Alembic 分别是什么？

**答：** SQLite 是存储数据的单文件数据库；SQLAlchemy 是 Python 的 ORM、查询和事务层；Alembic 是数据库结构版本迁移工具。磁盘 SQLite 会跨进程重启保留数据，只有 `:memory:` 数据库会随连接消失。

**记忆：** SQLite 是仓库，SQLAlchemy 是管理员，Alembic 是改造施工记录。

### `S` Q15：数据库迁移为什么不能只靠 `CREATE TABLE IF NOT EXISTS`？

**答：** `IF NOT EXISTS` 只能创建缺失表，不能可靠处理加列、改名、索引、约束和旧数据转换。Alembic 用版本脚本记录 `001 → 002 → 003`，新代码部署时逐步升级现有数据库且保留数据。

**记忆：** 建表解决“有没有”，迁移解决“怎么从旧结构变成新结构”。

### `A` Q16：WAL 模式是什么？

**答：** WAL 是 SQLite 的预写日志模式。修改先写入 WAL 文件，再合并回主数据库，使读取和写入能更好地并发，并提升异常恢复能力；SQLite 仍然是磁盘数据库，不是因此变成内存数据库。

**记忆：** 先记流水，再整理总账。

### `A` Q17：什么时候需要 Redis，什么时候 SQLite 足够？

**答：** SQLite 适合单实例、低中并发、需要简单持久化的首版；Redis 适合多实例共享缓存、分布式锁、限流、队列和短期高频状态。仅为了缓存天气和路线而引入 Redis，会增加部署成本。

**记忆：** 单机先 SQLite，多实例共享瞬时状态再考虑 Redis。

### `B` Q18：DuckDB 和 SQLite 是一个层面的东西吗？

**答：** 都是嵌入式数据库，但定位不同。SQLite 擅长事务型业务 CRUD；DuckDB 擅长列式分析、批量扫描 Parquet/CSV 和复杂聚合。项目可用 SQLite 存用户与订单，DuckDB 存大规模只读 POI 数据。

**记忆：** SQLite 管业务流水，DuckDB 做数据分析。

### `S` Q19：Saga 是什么，补偿动作是什么？

**答：** Saga 将跨服务事务拆成多个本地事务，每一步成功后记录对应补偿操作；后续失败时逆序取消已完成步骤。例如活动票成功、餐厅失败，则执行取消活动票。补偿不是修改一个状态字段，而是真正尝试执行撤销业务效果。

**记忆：** 数据库事务靠回滚，跨服务事务靠补偿；补偿也可能失败，因此要进入人工处理状态。

## MCP、可观测性与评测

### `S` Q20：MCP 和 Provider 有什么区别？

**答：** Provider 是项目内部对具体服务实现的抽象；MCP 是 AI Host 与外部能力之间的标准协议，支持 Tool、Resource、Prompt 和能力发现。真实 API、本地数据库、算法和 Mock 都可以作为 MCP Tool。

**项目回答：** 内部继续用 Provider；后期将完整规划、方案校验和方案查询作为 MCP Server 对外开放。

**记忆：** Provider 解决内部可替换，MCP 解决外部可互操作。

### `S` Q21：Trace、Span、Log、Metric 有什么区别？

**答：** Trace 是一次请求的完整轨迹；Span 是其中一个步骤；Log 是某时刻发生的事件；Metric 是大量运行的聚合指标。

**记忆：** Trace 看整趟旅程，Span 看一站，Log 看现场记录，Metric 看总体报表。

### `A` Q22：LangSmith 和 OpenTelemetry 有什么区别？

**答：** LangSmith 是面向 LLM/Agent 的观测与评测平台，可展示 Prompt、Token、Tool 和 Graph 运行；OpenTelemetry 是厂商无关的 Trace、Metric、Log 生成与导出标准，本身不是存储和 UI 平台。

**记忆：** OTel 是通用数据管道和插头，LangSmith 是 Agent 专用分析产品。

### `S` Q23：为什么现在就要规划评测？

**答：** 最终指标可以后测，但基线、固定样本和埋点必须提前保存，否则 V1 被覆盖后无法比较调用次数、Token、延迟和反问率。优先指标是端到端成功率、硬约束满足率、非必要反问率、P95 延迟、Token 消耗、工具降级和恢复成功率。

**记忆：** 评测不是最后打分，而是从第一版开始保留可比较证据。

### `S` Q24：Pydantic 契约解决什么问题？

**答：** 它把 LLM 输出、Graph 节点输入输出、Provider 返回和 API 响应从松散字典变成可验证模型，减少字段遗漏、类型漂移和错误传播。但数据库模型、Graph State 和 API DTO 不应强行共用同一个类。

**记忆：** Pydantic 是边界检查，不是把所有层粘成一个模型。

**面试准备优先级**

第一梯队必须能脱稿讲：`Workflow vs Loop`、`Graph 价值`、`State/Event/Envelope`、`代码路由与人工确认`、`Tool/Service/Provider`、`Checkpoint`、`Pydantic`、`评测指标`。

第二梯队重点准备工程取舍：`SQLite/SQLAlchemy/Alembic`、`Saga`、`SSE`、`MCP`、`Trace/LangSmith/OTel`、`真实工具降级`。

回答时统一使用这个结构最稳：

> **先定义概念 → 再说明为什么需要 → 再讲项目如何使用 → 最后讲没有采用另一方案的原因。**
