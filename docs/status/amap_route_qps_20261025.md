# 高德路线 QPS 节奏修正

_Current，2026-10-25，依赖 2015e55。根因证据已取得，真实服务器补丁验收待执行；不代表全量上线或吞吐指标。_

## 根因与复现

用户服务器日志显示多次 `api_rejected code=10021`，每次约 31–46ms。高德[官方错误码](https://lbs.amap.com/api/webservice/guide/tools/info)将其定义为账号使用某个服务接口的 QPS 超限。此前手动单路线成功、完整规划部分失败，是因为规划核验多个候选会产生多次连续出站；检查的最终 6 个路段不等于实际 HTTP 总次数。月调用总额度与每秒请求限制是不同维度。

新增确定性上游：模拟每秒只接收一次请求且每次耗时 35ms。原代码连续 6 路段及双线程调用均复现 10021→local_estimate（2 failed、1 passed 的先行回归），与实际失败边界相符。修正后同一场景不再降级。

## 修正

- 在已有 AmapRouteProvider 中加入共享锁、单调时钟与下次可请求时间；HTTP 完成后再留完整间隔，包含失败调用，不积累突发预算，不自动重试。
- 默认 HFT_AMAP_ROUTE_QPS=1，可按控制台配额设有限正数。当前单 worker 中所有规划共用同一 Provider，并发访客不各自获取一份 QPS；不协调同账号其他程序或额外进程。
- 原 ResilientRouteProvider 在缓存命中时直接返回，不进入出站等待。失败缓存、降级来源与硬约束保持原样，严格冒烟没有放宽。
- 不修改超时、坐标、路线解析、BGE、评分或模型调用次数。首次规划核验会增加等待；日志 Adapter 耗时包括节流等待，不能当作纯上游时延。
