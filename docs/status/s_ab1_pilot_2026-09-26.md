# S-AB1 Pilot Status — Legacy Multi-Agent vs Resume V2

The first bounded S-AB1 pilot is complete on experiment branch `codex/s-ab1-v1-v2`.

Compared revisions:

- Legacy Multi-Agent: `develop@90639f3`
- Resume V2: `planner-v2-eval-baseline` / `bef5fa3`

Six reviewed common cases were executed with a read-only legacy adapter and the existing V2 evaluation runner. Modification cases were excluded because the legacy graph has no equivalent structured replacement action. The clarification contract supplied fixed, human-reviewed answers and a three-turn maximum; no model was used to generate answers.

Results:

- Legacy single-turn baseline: `1/6` expectations. Five cases stopped in the legacy `SlotAgent` before planning because its broad required-slot gate requested budget or date. One unknown-date case correctly asked for the date.
- V2 B0 single-turn baseline: `5/6`, required assertions `21/23`, hard-constraint safety `3/3`, conflict diagnosis `1/1`, P50/P95 `1369/1857 ms`.
- V2 B3 single-turn diagnostic: `5/6`, required assertions `21/23`, hard-constraint safety `3/3`, Advisor acceptance `3/3`, P50/P95 `1838/6023 ms`.

The B3 pilot had three retrieval fallbacks because the BGE index was unavailable in that environment, so it is diagnostic only. The V2 failure in both pilots was `clarify_unknown_date`: the frozen input reached planning instead of the reviewed date clarification and needs a policy/path audit.

## S-AB1.1 multi-turn recovery pilot

The same six initial messages were replayed with fixed clarification answers.

- Legacy eventual success: **2/6**; clarification recovery: **2/6**. The successful cases completed after one answer. The remaining cases showed an unclassified follow-up question, a repeated `return_by` question, or a still-unresolved slot.
- V2 B0 eventual success: **6/6**; clarification turns: **0**. Five cases planned directly using defaults/recognized constraints. `clarify_unknown_date` also planned directly instead of asking for the required date, so its initial clarification-policy check was **0/1** even though eventual completion was successful.

This is intentionally reported as two dimensions: a reasonable first clarification is not a failure if the fixed answer allows recovery, while skipping a required clarification is an interaction-policy defect even when a plan is produced.

These numbers are not final architecture uplift metrics. The legacy system often terminates before its PlannerAgent, while V2 can continue with defaults and deterministic fallback. A formal comparison must explicitly choose either:

1. a product-level comparison that reports this early-stop behavior as a capability difference; or
2. a controlled planner-core comparison that supplies the legacy agent's required slots from the same reviewed fixture.

Before expanding to 12–20 cases, fix the V2 `clarify_unknown_date` policy/path mismatch, decide the product-vs-planner denominator, and make the BGE index available or explicitly exclude B3 from the pilot table.

No baseline source was modified; the adapter injects only a deterministic weather stub for the legacy app's missing external MCP dependency. Raw model outputs and secrets were not saved.
