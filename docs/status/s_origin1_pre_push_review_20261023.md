## 需要修复

1. **地图在父组件重渲染时重建（P2）**。`frontend/src/App.tsx:3123` 每次创建新的 `onOpenPoi`，而 `frontend/src/AmapPlanMap.tsx:170–207` 的地图构建 effect 依赖该回调及其他回调和 activeLegIndex；cleanup 会 destroy，重建后 setFitView。因此输入聊天内容等无关更新也可能重置用户的地图视角。需要稳定地图实例生命周期，并通过 ref/稳定回调处理事件；路段高亮独立更新。补一个父组件重渲染后实例与视角不被重置的假 SDK 测试。此项是静态代码证据，未连接在线 SDK 复现。
2. **未提交的启动脚本误判空 Key（P2）**。`scripts/start_backend_demo.ps1:72` 正则把 `AMAP_WEB_SERVICE_KEY=""` / `''` 识别为已配置，从而在 FullLlm 模式启用 live；Provider 对空 Key 的校验会令启动失败。正则匹配空引号已本机验证。应复用后端实际 dotenv/settings 的有效值判断，避免重复定义配置解析规则，不输出密钥。
3. **浏览器回归失配（验证门槛）**。完整 E2E 26 通过、10 失败、2 跳过，不能记录为通过。失败分类如下：
   - 4 项仍查找已删除的 `.conversation-heading.compact`（桌面固定框架/分栏、桌面和手机条件保存）。应按当前顶栏与 composer 的固定布局契约重新验证。
   - 2 项替换夹具只返回 1 个 replacement，却断言“替换 2 站”和第二站发生变化。应校验第一站替换、第二站锁定；不可让 UI 虚构服务端未返回的差异。
   - 4 项两站行程滚动测试要求出现返回顶部。诊断时桌面滚动容器 clientHeight/scrollHeight 均 836，手机均 751，实际 scrollTop 为 0，内容已完整显示。应准备真正溢出的长行程/短视口夹具，再保留滚动复位及末尾操作不被遮挡的断言。
