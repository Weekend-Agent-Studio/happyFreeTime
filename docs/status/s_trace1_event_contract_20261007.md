# S-TRACE1：安全执行事件合同

状态：完成（仅合同与接口，不接入运行阶段，不接 SSE）

## 目标

为创建、约束 Patch、反问恢复和单站修改定义同一份用户安全的执行事件合同。该合同描述“本轮执行到了哪一步”，不替代已有的模型诊断、检索证据、Provider 事实或搜索 Trace。

## 数据职责

| 数据 | 作用 | 是否进入公开执行时间线 |
| --- | --- | --- |
| `PlanningRunEvent` | 阶段开始、完成、回退、失败或等待输入 | 是 |
| `RuntimeDecision` | 模型/适配器调用、尝试次数、token、fallback 诊断 | 否，保留为诊断详情 |
| `SearchTrace` | Beam/Legacy 搜索扩展、剪枝和路线请求汇总 | 否，保留为评测与开发者详情 |
| `Evidence` / Provider facts | 支撑方案结论的事实 | 否，进入方案依据 |
| `Warning` / degradation | 风险和降级原因 | 否，进入风险区 |

## 合同不变量

- `PlanningRunTrace` 中的事件属于同一个 `run_id`，并从 1 开始连续编号。
- `public_details` 只允许有限的操作、字段、模式、计数、版本和安全原因码；不允许任意日志字典。
- 不保存 Prompt、模型原始响应、隐藏推理、token 明细、凭据、请求头、堆栈或原始异常文本。
- `waiting_input` 是正常的交互终态，不表示系统失败。
- 事件合同不参与 Graph 路由和业务决策。

## 当前范围

本切片只新增领域合同、HTTP 响应可选字段和前端类型声明。实际阶段接入、完成后投影、UI 时间线和 SSE 由后续 S-TRACE2–4 负责；当前行为和结果没有改变。
