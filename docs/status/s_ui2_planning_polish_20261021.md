# S-UI2 第一批：正常规划与行程可读性

分类：Current branch snapshot。2026-10-21。从最新 `origin/main@7a67e22` 创建 `codex/s-ui2-planning-polish`。用户提供的 UI/UX 评审是设计输入，不作为已确认缺陷或必须逐条复制的命令。本批只处理正常规划体验，不代表评审全量完成。

## 独立复核与优先级

| 区域 | 代码/截图证据与判断 | 本批决定 |
| --- | --- | --- |
| 候选卡片 | 1024px 时指标和详情操作挤在一行，时长/费用逐字断行；标题只能一行，指标 11px | 修复指标完整短语、操作换行、标题两行和可读字号 |
| 方案前辅助信息 | 结构化条件、天气和语义需求混在推荐解释中，部分标签重复 | 条件摘要与需求重点分组、去重，并在候选卡片前常显；全局风险继续可见 |
| 右侧时间轴 | 来源/交通按钮 9px，路线/停留/类型/标签 10px | 改为 12px 次级、13px 时间/指标、16px 地点名称；不改变 RouteLeg 顺序或事实 |
| 开发诊断 | `VITE_SHOW_DEVELOPER_DETAILS !== "false"` 默认展示 | 改为显式 `true` 开启；公开过程、核验与来源继续可查 |
| 正常成功文案 | “都可行”容易被读作实时营业/预约保证 | 改为“根据当前条件，整理了 N 个候选方案” |
| 日期/POI/矮屏 | main 已有月历、精确时间输入、紧凑 POI 返回栏、弹窗滚动与焦点恢复 | 保留，不按旧截图重复开发 |
| 恢复与替换 | 动作同层渲染、替换面板双列拥挤确有风险 | 下一批单独处理；只能基于动作类型分组，不凭前端推断成功率 |
| 聊天自动滚动 | effect 随 messages/loading 变化调用 scrollIntoView，尚无主动阅读历史的跟随策略 | 后续定向交互切片，不和本批排版混写 |
| 导航宽度/全局样式 | 244px 不必机械改为220px；新 ui-polish.css 会形成额外覆盖层 | 保留当前导航宽度，不加载用户提供的补丁/覆盖 CSS，不新增覆盖层 |
