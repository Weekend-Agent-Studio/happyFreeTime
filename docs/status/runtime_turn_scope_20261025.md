## 复现与原因

用户报告规划结构/召回在多轮回复中出现两组。固定示例也可复现：条件保存带出初始轮三条记录，明确重规划和恢复确认将旧 planning_intent/candidate_retrieval 与当前轮追加记录一起返回。Graph 正常解释入口会重置记录，但结构化条件编辑、重新规划及 interrupt resume 绕过该入口，导致 checkpoint 中前轮诊断遗留。

另一个展示问题：前端只要 fallback_reason 非空就标成黄色“回退”，但 structured_command、复用已有结构等原因表示正常绕过模型。模型调用为 0、结构化操作直达不代表模型失败。
