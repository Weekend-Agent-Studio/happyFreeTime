# HappyFreeTime 产品想法收集箱

_记录临时想法、未决需求和可能的改进方向 · 最后更新：2026-08-14_

---

> ⚠️ **非实现契约：** 本文档中的条目默认只是想法。Codex 或其他协作者不得因为读到条目就自动实现；只有用户明确确认，并将条目晋升为路线图任务、Issue 或 ADR 后，才能进入开发。

## 📋 使用规则

每条想法使用独立编号，避免一次讨论把多个需求隐式绑定。新会话应先查看状态，再决定是讨论、验证、拒绝还是晋升，不得把 `captured` 或 `exploring` 当作已批准需求。

| 状态 | 含义 | 是否允许实现 |
| --- | --- | --- |
| `captured` | 已记录，尚未分析 | 否 |
| `exploring` | 正在讨论方案与取舍 | 否 |
| `accepted` | 用户已确认，等待进入正式计划 | 仅在明确实施任务中 |
| `promoted` | 已进入路线图、Issue 或 ADR | 按正式规格执行 |
| `rejected` | 明确不做，保留原因 | 否 |
| `implemented` | 已实现并验证 | 不重复实现 |

## 🎯 晋升为正式需求的条件

条目进入实现前至少补齐以下内容：

- 用户故事与实际问题
- 可观察的验收标准
- 明确不做的范围
- 所属里程碑与优先级
- 数据契约或交互变化
- 自动测试与人工验收方式
- 与现有架构基线是否冲突
